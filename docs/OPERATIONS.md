# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。

## 客户编号切换（迁移台 `/migration`）

1. 在迁移台上传含 `mapping` 与 `transaction` 两类记录的 CSV，先用「迁移预览」核对，预览不入库。
2. 核对「新客户台账」与三栏结果：已归客户交易、待核交易、隔离行。新旧编号都命中的交易停留在待核，原签约编号、命中行号与映射作为待核依据随证据留档。
3. 待核交易不改挂、不进新客户台账；修复隔离行后重新上传，历史迁移批次保留。
4. 四项守恒全部成立且无隔离行时「签发」才可点击；未对平强行签发返回 409，旧版归属与待核依据保持不变。同一来源重复执行命中同一批次，不会重复入库或改变归属。
5. 签发或暂缓后下载迁移证据（`migration-evidence/1`），连同待核依据一并交接审计。
